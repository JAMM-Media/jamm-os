# JAMM PX — Standing Instructions

Read How_We_Work_Process_Rules.md in full before starting any task. It covers how work gets verified and debugged in this repo, and it exists because the same class of failure has recurred again and again — the instance list inside it is current, and it grows. Do not skip it because a task looks small or well understood.

Additionally, before any task involving the Concierge agent (backend routes, prompts, frontend chat UI, tools, or knowledge corpus), read JAMM_PX_Perfect_Assistant_Build.md in full. It is the standard the Concierge is being built toward, and every Concierge related task should be traceable to something described in it.

While a build session is live in this checkout, any second terminal session is READ ONLY: no commits, no pulls, no pytest runs, no file writes. Side-quest questions get answered from reads alone; anything needing a write waits for the build session to close or gets its own task file. This exists because on August 17, 2026 a parallel session's mid-build pulls and an unannounced commit left the running session's test baseline stale and produced a two-head alembic merge that had to be resolved before anything could be pushed.
