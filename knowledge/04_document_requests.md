## Document Requests > Overview > What a Document Request Is

A document request is a structured checklist sent to a client asking them to upload specific files. Each request contains one or more checklist items. Each item has a label, an optional description, and a required or optional flag.

Document requests are also called document checklists, upload requests, or client document tasks in some other practice management tools. In JAMM PX the term is always document request.

A document request must be linked to both a client and an engagement. Create the engagement before creating the document request.

---

## Document Requests > Overview > Document Request Statuses

A document request has one of three overall statuses. The status rolls up automatically from the individual checklist item statuses. Staff do not set the overall status manually.

Pending means no items have been uploaded yet. This is the status when the request is first created and sent.

Partial means at least one item has been uploaded or approved, but not all required items are complete.

Complete means all required checklist items have been approved by a staff member. JAMM PX sets this automatically when the last required item is approved.

---

## Document Requests > Overview > Checklist Item Statuses

Each item inside a document request has its own status independent of the overall request status.

Pending means the client has not yet uploaded anything for this item.

Uploaded means the client has submitted a file for this item and it is waiting for staff review. Staff must review uploaded items and either approve or reject them.

Approved means a staff member has reviewed the file and accepted it. Approved items count toward request completion.

Rejected means a staff member has reviewed the file and determined it is not acceptable. The client must re-upload a corrected file. When a client re-uploads after a rejection, the item status resets to uploaded for staff review again.

## Document Requests > Creating a Document Request > How to Create a Document Request

Navigate to the engagement the document request belongs to. Open the engagement detail page and select the Document Requests tab. Click New Document Request.

Give the request a title that describes what you are collecting. Examples: 2024 Tax Return Documents, Q1 Bookkeeping Source Files, Estate Documents.

Add checklist items. Each item requires a label. Add an optional description to give the client more context about what is needed. Mark each item as required or optional. Required items must be approved before the request reaches complete status. Optional items do not block completion.

Set an optional due date to show the client a deadline in the portal.

Save the request. The request is created in pending status and is visible in the engagement.

---

## Document Requests > Creating a Document Request > Adding Checklist Items

Each checklist item has three fields: a label, a description, and a required flag.

The label is the name of the document. Examples: 2023 W-2, Bank statement January, Prior year tax return, Social Security card.

The description gives the client additional context. Examples: Your W-2 from your primary employer for the 2023 tax year. The January statement for your primary checking account. This field is optional but reduces client confusion and follow-up questions.

The required flag controls whether the item must be approved for the request to reach complete status. Mark items as required when the engagement cannot proceed without them. Mark items as optional for supplementary documents that are helpful but not essential.

Add as many items as needed. There is no limit on the number of checklist items per request.

## Document Requests > Sending a Document Request > How to Send a Document Request to a Client

The client receives the document request through their portal. The request appears on the To-do tab in the client portal as an action item with an Upload button.

For the client to see the request, they must have portal access enabled. Navigate to the client record and confirm that portal access is active. If the client does not have portal access, send them a magic link to activate their portal before sending document requests.

The request becomes visible in the portal as soon as it is created. There is no separate send step required to make it appear.

---

## Document Requests > Sending a Document Request > Sending a Reminder

Open the document request from the engagement detail page. Click Send Reminder. JAMM PX sends the client an email reminder that they have outstanding items to upload.

JAMM PX tracks how many reminders have been sent and when the last reminder was sent. This prevents accidental duplicate reminders and gives staff visibility into how many times a client has been contacted.

The automation system can also send reminders automatically. See the Automation Presets module for details on the document request reminder preset.

---

## Document Requests > Reviewing Uploaded Documents > How the Review Flow Works

When a client uploads a file for a checklist item, the item status changes from pending to uploaded. Staff receive a notification that a file is ready for review.

Open the document request from the engagement detail page. Find the item with uploaded status. Review the file. Click Approve to accept the file or Reject to send it back to the client.

Approving the item moves its status to approved. If this was the last required item, the overall request status moves to complete automatically.

Rejecting the item moves its status to rejected. The client sees the rejection in their portal and must re-upload a corrected file.

---

## Document Requests > Reviewing Uploaded Documents > Approving a Checklist Item

Open the document request inside the engagement. Find the checklist item and change its status to approved. Once all required items are approved the request status automatically updates to complete.

Approval confirms that the file meets your requirements. Approved files are stored on the engagement and are accessible to staff from the engagement document tab.

---

## Document Requests > Reviewing Uploaded Documents > Rejecting a Checklist Item

Open the document request inside the engagement. Find the checklist item and change its status to rejected. The item status resets to uploaded when the client re-uploads. Review the new file and approve or reject it again.

Use rejection when the client uploaded the wrong document, an incomplete file, or a file that does not meet your requirements. The client can see that the item was rejected in their portal.

---

## Document Requests > Reviewing Uploaded Documents > Waiving a Checklist Item

A checklist item can be waived by a staff member. Waiving an item marks it as resolved without requiring the client to upload anything. Use waiving when you have obtained the document through another channel or have determined the item is no longer needed.

Open the document request inside the engagement. Find the checklist item and change its status to waived. Waived items do not block the request from reaching complete status.

---

## Document Requests > The Client Experience > What the Client Sees

Clients access their document requests through the client portal. The portal is a separate interface from the staff application. Clients log in using a magic link sent to their email address.

When a client opens their portal, the To-do tab shows all pending action items including document requests. Each document request appears as a card with the request title, an optional due date, and an Upload button.

The Documents tab shows files that have been shared with the client by the firm. Documents uploaded by the firm are listed here. The client can download these files.

---

## Document Requests > The Client Experience > How a Client Uploads a Document

The client opens their portal and navigates to the To-do tab. They find the document request card and click the Upload button. They select a file from their device. Accepted file types are PDF, Word documents, Excel files, PNG, and JPG images.

After uploading, the item status updates from pending to uploaded in the firm's view. The client sees the item marked as submitted in their portal.

If a staff member rejects the upload, the client sees the item flagged in their portal and can upload a replacement file using the same Upload button.

---

## Document Requests > The Client Experience > What the Client Sees After Uploading

After uploading a file, the client sees the checklist item marked as submitted in their portal. They can see which items are still pending, which are submitted and awaiting review, and which are approved.

Once all required items are approved and the request reaches complete status, the client sees the request marked as completed in their To-do tab. Completed requests move to the completed section in the portal.

## Document Requests > Common Issues > Client Says They Cannot See the Document Request

If a client says they cannot see a document request, check these things in order.

First, confirm the client has portal access enabled. Navigate to the client record in JAMM PX and check that portal access is active. If it is not active, enable it and send the client a magic link.

Second, confirm the client is logged into the correct portal. Clients access the portal through a magic link tied to their email address. If they are using an old magic link it may have expired.

Third, confirm the document request is linked to the correct client. Open the engagement and verify the document request is visible in the Document Requests tab.

---

## Document Requests > Common Issues > Client Cannot Upload a File

If a client says they cannot upload a file, check these things in order.

First, confirm the file type is supported. Accepted types are PDF, Word documents, Excel files, PNG, and JPG. Other file types are not accepted. Ask the client to convert the file to a supported format.

Second, ask the client to try a different browser or device. Mobile browser compatibility can vary.

Third, confirm the document request is still in pending or partial status. If the request is already complete, the Upload button may not be available.

---

## Document Requests > Common Issues > Request Shows Partial But Should Be Complete

If a document request shows partial status when you believe all items are uploaded, at least one required item is not yet in approved status. Uploaded items are not the same as approved items.

Open the document request and review each required item. Any item with uploaded status needs staff review. Approve each uploaded item. Once all required items are approved the request status updates to complete automatically.
